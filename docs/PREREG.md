# 实验协议

本文说明 ctxroute 的实验设计、运行冻结、停止规则与分析方法。运行计划将本文件与源码、配置、价格和划分一同纳入哈希校验。具体执行集合与限额由生成的计划及其冻结配置确定，不从模型结果反向选择。

## 研究问题

- H1：任务成功与轨迹长度、上下文长度的关系，作为观察性诊断。
- H2：结构化压缩对缓存感知成本和任务成功率的影响。
- H3：步骤级模型路由对成本、延迟和任务成功率的影响。

若采用非劣分析，应在运行前固定边界，例如成功率差下界不低于 `-δ`，并使用预先声明的置信区间。小规模 pilot 用于检验链路与测量行为，不支持总体非劣结论；未显著不等于等效。

## 数据与泄漏控制

数据来源、revision、源文件哈希、划分算法和 dev/test ID 列表保存在 [`data/split.json`](../data/split.json)。当前划分基于 `princeton-nlp/SWE-bench_Lite` 的 300 个 upstream test 实例，按 `SHA256(seed + ":" + instance_id)` 排序，前 60 项为 dev，其余 240 项封存为 test。

计划器只允许固定 dev 前缀 1–5 项与 `seed=20261022`。实例顺序不得根据结果替换，正式 test 或多 seed 实验需要独立设计和执行支持。若供应商不支持请求 seed，记录该标识的调度含义，不声称模型生成确定性。

Agent 输入仅包含 `instance_id`、`repo`、`base_commit`、`problem_statement`。gold patch、`test_patch`、提示和判分字段不得交给 Agent。构建与审计推理镜像时应检查仓库历史、标签、reflog 和隐藏答案泄漏。判分使用独立官方 harness 环境及测试规范。

## 实验臂与控制变量

| 臂 | 配置 |
|---|---|
| A0 | mini-swe-agent 原生文本强模型基线 |
| A1 | ctxroute 强模型，无压缩、无路由 |
| A2 | A1 加结构化压缩 |
| A3 | A1 加规则路由 |
| A4 | 压缩与路由联合配置 |
| A5 | ctxroute 固定廉价模型 |

主配对为 A2–A1、A3–A1，A4–A1 检查联合配置；A2/A4 的仅截断变体用于区分摘要与截断行为。A0 作为外部系统参考，其提示、动作协议、输出模板和传输差异见 [A0_ADAPTER](A0_ADAPTER.md)，不用于单独归因压缩或路由效果。A6/A7 是未接入执行器的扩展配置。

同一实例各臂固定任务描述、镜像摘要、模型版本与思考设置、工具资源限制和任务限额。臂顺序由计划冻结并记录，缓存和时间顺序偏差作为比较局限。压缩臂的 `recall` 可用性差异也需报告。

压缩阈值、最近步骤数、路由锁、输出截断、格式纠错和进展控制均由实验配置控制。具体动作与停止语义见 [ACTION_PROTOCOL](ACTION_PROTOCOL.md)、[PROGRESS_CONTROL](PROGRESS_CONTROL.md)。改变任何条件须生成新计划。

## 预算与停止规则

全局硬上限、暂停阈值及费用类别来自 [`configs/budget.json`](../configs/budget.json)，各臂步骤、墙钟、命令、输出与费用限制来自 [`configs/arms/`](../configs/arms/)。动作、压缩、重试和辅助请求共用账本；云计算、存储和网络等外部费用分别登记。

每次请求前按保守输入护栏、最大输出和费率预留费用。未知 usage 保留未结算预留，超出护栏或预留则记录并锁停。开始实例前检查其剩余各臂的完整费用额度，不能在中途缩减集合以回避预算终止。

预算账本按运行范围累计已结算成本与未结算预留；只有明确满足非高峰条件的请求才按对应费率结算，时段不确定时保留预留。A1–A5 的执行循环还累计模型返回的高峰价成本上界，作为独立的保守单任务停止条件。因此，`budget_limit` 可能在已结算 usage 费用低于配置额度时发生；分析需注明触发的是账本预留检查还是本地成本上界检查。

本地成本上界在响应返回后检查。若该响应使累计上界超过任务额度，请求记录与 usage 已写入，但动作尚未执行，也可能尚未写入步骤 trace。核对请求数、动作数和停止原因时应保留这一区别，不把缺少动作记录当作未产生费用。

模型请求尝试次数由 runtime 配置控制，最多两次；格式失败达到 `format_attempts` 后终止。步骤、墙钟、上下文、输出、重复动作和沙箱错误均记录明确终止原因。中断任务不自动恢复或重复付费请求。修复实现后的复测使用新计划，引用旧运行而不覆盖。

## 判分与缺失

仅使用官方 SWE-bench harness 判分，保留 harness 版本、判分 run ID、预测哈希和报告哈希。空补丁、格式错误、预算终止、模型失败和基础设施错误分别记录，不把提交动作或非空补丁当作成功。

报告逐臂已启动、已完成、已判分、空补丁和缺失数量。非成功任务不得从已启动分母删除，未开始任务单列。官方可能跳过空补丁而不产生逐实例报告，应结合官方汇总解释分类，不能将缺失报告直接转为已执行测试。主配对仅纳入定义完整的实例，列出被排除项与原因。

## 分析方法

保留逐实例原始数据及失败案例。二元成功采用精确双侧 McNemar，零不一致对时 `p=1`；实例级配对差与成本、延迟比值采用固定 seed 的 bootstrap。至少两个完整实例才输出 bootstrap 区间，默认重采样 10,000 次。

成本包含缓存命中与未命中输入、输出、压缩及重试；usage 估算、费用上下界和供应商账单分开。缺失 usage 不进入完整费用配对。成本与延迟比值使用中位数；零分母标为不可定义并报告绝对差，不添加任意 epsilon。P95 必须同时报告样本数。

同题复测与不同实验臂不是独立任务样本。短轨迹或提前失败带来的低成本不能直接解释为优化收益；效果结论需结合成功率、终止原因和完整配对。分析实现见 [`evalkit/analysis.py`](../src/ctxroute/evalkit/analysis.py) 与 [`evalkit/statistics.py`](../src/ctxroute/evalkit/statistics.py)。
