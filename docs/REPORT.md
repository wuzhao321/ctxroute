更新：2026-10-24。首个固定 dev 实例的 A0–A4 真实推理已完成，五臂全部为空补丁。完整逐臂结果、官方汇总及费用见 [PILOT_REPORT](../results/analysis/arm64-smoke-20261024/PILOT_REPORT.md)。正式 test 未测，不能据此声称成功率、压缩或路由收益。

## 方法与实现

目标仍是比较结构化上下文压缩、步骤级模型路由对含缓存成本、延迟和任务成功率的影响。划分、假设和预算规则见 PREREG.md；正式 test 暂缓，当前只允许固定 dev pilot。A0 为原生文本外部参考；A1 是内部对照，A2/A3/A4 分别加入压缩、路由与二者联合。A5 已有代码但本轮 pilot 未纳入。

核心实现包括任务循环、四分区上下文、批量压缩、证据化历史观察、规则路由、预算预留、MCP/Docker 适配、不可变计划、预测导出及统计分析。结构化记忆和分阶段复现分别见 STRUCTURED_MEMORY.md、REPRODUCE.md。A0 与 A1 的提示和动作接口不同，不能将二者差异直接归因于压缩或路由。

## 局限与后续

本机 ARM64 隔离环境可用，官方 harness 3.0.17 构建成功。模型没有产出可执行补丁，官方汇总将其归为空补丁并跳过测试；独立人工 marker 负对照实际执行了官方测试，结果未解决且无基础设施错误。负对照不计入模型成绩。摘要 schema 检查不证明摘要语义正确；P1 引用只证明工具曾返回该文本，不能证明命令输出或后续仓库状态正确。

工作流提供官方判分命令和证据交接，不自动创建环境或认证外部报告真实性。原始 JSONL/CSV 为当前存储方案；DuckDB/Parquet、学习路由、本地模型、A2A 及外部 harness 对照仍后置。下一执行阶段需先落实隔离环境与预算、重新冻结清单，再开展固定 dev 样本；无法满足资源约束则保留未测状态。
