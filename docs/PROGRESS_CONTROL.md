# 运行进展与命令分类

[`orchestrator/progress.py`](../src/ctxroute/orchestrator/progress.py) 为 A1–A5 提供运行状态和重复动作控制。参数配置于各实验臂的 `progress` 字段；A0 保留上游原生循环行为。

## 重复动作控制

| 参数 | 默认值 | 行为 |
|---|---:|---|
| `repeat_warn_after` | 2 | 连续相同命令、完整输出、退出码与补丁达到阈值时提示重复 |
| `repeat_block_after` | 3 | 达到阈值后拦截再次执行同一命令 |
| `max_blocked_repeats` | 2 | 连续拦截达到阈值时以 `stagnation` 结束 |
| `final_step_warning` | 10 | 剩余动作达到阈值时提示优先编辑、验证和提交 |
| `edit_prompt_after` | 6 | 执行达到指定命令数仍无补丁时，提示形成最小实现修改 |

默认设置允许最多三次相同命令与结果组合。后续同一命令会被拦截，反馈引用最近一次实际执行的步骤及退出码，并标明本次提案未执行和剩余拦截次数。连续两次被拦截时停止。模型请求已发生，因此被拦截的动作仍计入步数与预算。新动作可继续执行，观察签名变化时重置连续计数。

检测仅比较命令、输出、退出码和补丁的连续签名，不推断任务是否成功，也不能识别所有循环。它可能限制有意轮询，应作为可记录的实验控制条件。

## 运行状态

P0 `RUN STATUS` 包括剩余动作、墙钟、保守本地费用额度、补丁是否非空、增删行数及重复次数。编排器在动作请求前刷新状态，将压缩消耗的时间和费用计入。该部分的 token 纳入上下文预算，不属于 P1 引用事实，也不是模型推断。

每次正常返回的 `bash` 命令之后，编排器获取实际 `git diff`；命令失败也可能已经修改文件。超时或输出超限按沙箱终止规则处理。补丁存在不代表修复正确，忽略文件和仓库外状态也不由该 diff 覆盖。

## 保守命令分类

[`router/rules.py`](../src/ctxroute/router/rules.py) 的分类器版本为 `literal_cd_single_command_v2`。它识别有限只读命令、测试命令，以及一个字面量 `cd` 前缀加 `&&` 后的单条命令，例如：

```sh
cd src && cat module.py
```

分类过程不改写发往沙箱的原始命令。Python 脚本、多段复合命令、重定向、替换、管道及无法识别的命令归为 `edit_or_unknown`；带编辑选项的 `sed` 不按只读处理。分类用于路由启发式，不替代沙箱隔离。

路由还要求满足无错误历史、上下文阈值和强模型锁条件，识别为只读并不保证下一步切换到廉价模型。重复动作被拦截时触发强模型锁。

## 下一动作指引

`progress.edit_prompt_after` 控制无补丁时的编辑提醒，默认在执行 6 条命令后生效；重复结果达到警告阈值也会提前提醒。该阈值改变建议，不增加或放宽执行额度。

进展状态提供 `next_priority` 和 `next_action`：初始为 `investigate`；无补丁且达到提醒条件时为 `edit_needed`；补丁出现或变化后为 `verify_patch`；可识别测试命令返回非零时为 `repair_patch`，返回零时为 `review_and_submit`。指引同时置于用户上下文末尾的 `NEXT ACTION` 段，提示生成新的动作，而非复制历史命令。该段与运行状态均计入上下文估算和限制。

`local_test_status` 仅表示识别出的测试命令退出状态，不表示测试覆盖充分、修复正确或官方判分通过。它绑定到 `local_test_patch_sha256`；任何已观察到的 diff 变化都会清除旧验证状态，测试命令自身修改 diff 时也不会记为已验证。普通 Python 复现脚本不自动计为测试。状态无法反映 git diff 之外的环境、忽略文件或外部状态变化。

测试运行器缺失、导入或收集失败、调用参数错误和无测试执行会记录为 `not_run`，并保留可识别的诊断。编排器根据该状态引导恢复测试环境或改用可执行的公开检查。测试断言失败的修正指引以已执行测试的证据为依据。

默认建议不强制编辑或提交，模型仍可在证据不足时继续调查；重复动作拦截、费用与墙钟限制继续独立生效。A0 原生循环不使用这些指引。模型输入、配置和源代码变化需要新的实验计划。

## 可选的首次编辑检查点

`progress.first_edit_checkpoint` 默认为 `false`，原实验臂的指引与停止行为保持不变。[`A1-first-edit.yaml`](../configs/variants/A1-first-edit.yaml) 在 A1 配置上启用此候选策略；它不代表已冻结或获准执行的实验。

启用后，在至少执行 `edit_prompt_after` 条命令、仍未观测到非空 diff 时，指引按证据缺口变化：

| 可观测状态 | `next_priority` | 下一动作指引 |
|---|---|---|
| 未识别到源码读取 | `locate_source` | 读取一处相关 Python 源码，而非继续列目录或宽泛搜索 |
| 已读源码，未识别到诊断 | `diagnose_before_edit` | 执行一次聚焦复现或仓库测试，比较预期与实际行为 |
| 已读源码且诊断已完成 | `make_first_edit` | 根据证据作最小实现修改；若存在具体疑点，可先作一次针对性检查 |

源码证据只识别成功且有输出的简单 `cat/head/tail/sed` 命令，末个参数须为 `.py` 文件；兼容已有分类器支持的字面量 `cd` 前缀。诊断证据识别有输出的测试命令（退出码 0 或 1），以及成功的 `python/python3` 脚本、`-c`、`-m` 或标准输入脚本。它们只是候选证据，不证明文件与缺陷相关、原因已定位或复现有效；复杂命令可能无法识别，普通 Python 诊断也不因此计为通过测试。此识别不改变安全分类或实际执行的命令。

检查点建立后，最多允许 `max_no_edit_commands` 条后续已完成的 `bash` 命令仍返回空 diff，默认 2 条。达到阈值以 `edit_not_reached` 结束；更换读取范围或再次复现不会重置计数。重新渲染状态不消耗额度，被格式校验或重复动作控制拦截的命令不执行。全部已发生模型请求照常计入费用，现有预算、步数、墙钟和沙箱停止规则继续生效。

只有实际观测到非空 diff 才记录首次编辑，不依赖命令名称或退出码。首次编辑后回到现有的 diff 绑定验证流程；后来撤销补丁不会抹去首次编辑历史，也不重新启用此检查点。无补丁提交仍如实记录为空补丁。该策略不生成编辑、不放宽动作校验，也不保证补丁有用或正确；不得为了通过检查点作无关改动。

## 可选的编辑后验证检查点

`progress.post_edit_checkpoint` 默认为 `false`，不改变原始臂或仅启用首次编辑检查点的行为。[`A1-edit-verify.yaml`](../configs/variants/A1-edit-verify.yaml) 同时启用两个检查点，输出上限为 8192；这是候选配置，不是付费实验授权。

该策略只改变下一动作指引和可见测试记录，保持原有动作格式、校验、工具执行、费用及停止规则。准备编辑时，提示先确定共享函数及调用方必须保留的输入行为，并选用相关公开测试。补丁存在后，指引如下：

| 当前 diff 的证据 | `next_priority` | 决策指引 |
|---|---|---|
| 尚无已识别的测试结果 | `verify_regressions` | 检查修改范围，选择覆盖目标行为与原有行为的最小公开测试集合，尽量合并执行 |
| 测试命令返回非零 | `repair_patch` | 先区分断言失败与收集/环境错误，依据具体失败修复并复测 |
| 测试命令返回零 | `submit_decision` | 检查实际运行情况及覆盖范围；仅补充具体缺失的回归检查，否则提交，避免重复成功检查或继续无目标探索 |

启用时状态额外显示 `local_test_command`、`local_test_step` 和 `test_coverage=not_established_by_exit_code`。命令、步数和已有测试状态均绑定当前 diff；补丁变化后清空，测试命令自身修改 diff 时不计为已验证。状态渲染不执行命令，也不消耗动作额度。

编排器不推断测试覆盖、不解析测试结果为官方正确性，也不宣称已完成差异审阅。覆盖充分性及提交仍由 Agent 判断，不强制增加测试次数或自动提交；少量测试通过仍可能遗漏回归。合成动作测试只能证明状态传递和执行路径，实际选择测试与提交的能力需要新的冻结配对实验验证。任务 Agent 的信息边界不变，不向其提供官方隐藏测试或参考补丁。

## 复现失败与历史测试证据

测试和复现命令应传播真实失败：使用断言、`subprocess.run(..., check=True)` 或以子进程退出码退出。仅打印子进程状态或在失败后执行成功的 `echo`，不能让外层命令的 0 成为验证通过依据。

对已观察到的 Python 包装脚本形式，进展状态补充有限的失败信号：命令以 `python` 或 `python3` 开始、包含 `.returncode`，且完整输出以独立的 `exit N` 行结尾时，记录非零子进程状态。它是未经独立证明的输出报告，不是通用 shell/测试框架解析器，也不重写命令或改变实际退出码。源码读取、超时或截断输出不据此判定；报告 0 也不自动计为仓库测试通过。

非零报告会撤销先前的通过提示，并在 `reported_child_exit_code`、`reported_check_step` 中给出证据来源，优先检查失败并修正。若同一命令还改变了 diff，`reported_check_changed_patch=true` 明确表示不能仅凭信号确定检查与编辑的先后；应先核对当前补丁。普通读取和动作格式错误不会清掉该信号；补丁变化使旧信号失效，后续完整测试仍需重新验证。

固定记忆中的 `last_failed_test` 带步骤、命令实际退出码、可选子进程状态、当时 diff 哈希和历史含义。编辑后保留失败观察，但明确可能过时；另一条测试返回 0 不会删除先前失败，因为测试覆盖范围未必相同。当前 diff 的测试状态与旧补丁的失败证据分别记录，Agent 应结合测试范围作判断。这些通用动作表示与失败反馈改动影响所有 ctxroute 实验臂，后续对照必须共同冻结新源码和 Prompt；不改变 A0 的上游循环。

## Trace 与分析

验证结果由独立的证据识别器处理，不依赖路由的保守 `command_class`，也不改写执行命令。支持直接测试和只读前缀后的最终测试，例如 `git diff && python -m pytest ...`；前缀失败且无测试输出时不归因到测试。更复杂的 shell 仅在检查命令与失败诊断相符时保守记录失败，不把外层退出 0 当作通过；收集、帮助、版本命令也不构成通过。

`check_evidence` 保存命令、作用范围标识、显式测试选择器、实际外层退出码、可归因时的测试退出码、归因方式、前后 diff 哈希及步骤。不能证明子测试退出码时记录 `null`。改变 diff 的命令不验证新 diff；局部通过仅替换相同调用范围或相同 pytest 选项下明确包含的选择器集合，不清除其他范围的失败。不同目录、筛选选项和不透明复现均不推断覆盖关系。`local_test_evidence` 显示当前 diff 的全部有效范围记录，`last_failed_test` 保留历史失败。范围标识不是行为覆盖率，官方判分仍独立。

trace 保存 `command_class`、`command_classifier_version`、`progress` 和 `executed`。拦截记录为 `executed=false`、`repeated_action_blocked`，分析以 `blocked_repeat_actions` 与实际执行的重复命令区分。

已执行工具的 trace 另存 `patch_present_after`、`patch_sha256_after` 和 `edit_progress`。未观测到 diff（如 recall、超时、输出超限）时前两项为 `null`，不能推断未编辑。`edit_progress` 保存源码/诊断步骤、检查点步骤、无 diff 命令数以及 `first_edit_step`；后者使用实际 Agent 步数，包含此前格式错误消耗的步骤。最终 manifest 也保存 `first_edit_step`，始终未观察到编辑则为 `null`。这些指标不加入默认策略的模型输入。首次非空 diff、最终非空补丁、同一 diff 的测试结果和官方 resolved 应分别报告。

分析优先使用执行时记录的分类；缺少分类字段的旧轨迹采用分析版本的回退逻辑。复现历史分析应使用对应源码版本。改变提示、停止规则或分类器后应冻结新计划，以保留比较条件。

## 可选的公开回归选择与修正策略

`progress.regression_strategy` 默认关闭，现有 Checkpoint 的提示和决策保持不变。开启后，编排器在每次 diff 改变时，在任务容器内静态读取基线公开 Python 源码、当前改动和公开测试；不导入或执行待测仓库来构建调用关系，不读取官方判分字段。依据变更函数、直接调用及有限层调用者选择已有公开测试，把新增测试函数单列为目标测试。类构造仅关联构造方法，不假定调用所有方法。静态选择不能证明全部行为覆盖；无法形成有界选择、变更文件语法不明或修改已有测试函数时，不能获得提交资格。

自动测试使用单个 `python -m pytest` 调用，每个文件分别执行，记录目标/回归类别、选择器、前后 diff、完整输出及退出码。每次自动测试占用一个原有步骤，共享总墙钟、配置的工具时限和隔离资源，不额外增加模型请求额度。选择器读取也是有界工具操作，计入墙钟并保留独立记录。失败会暂停剩余自动测试并把具体输出交给模型；修正 diff 后重新选择并验证。

已知补丁后失败跨 diff 保留，仅相同检查或明确包含原选择器的成功复测可清除。目标测试通过不能代替调用者回归，补充诊断失败不能被无关测试掩盖。模型仍使用原有 JSON/bash/submit 协议；编辑应与检查分离，复现应直接暴露错误并传播退出码。无法归因的复杂脚本不授予通过。

失败后最多允许 `repair_diagnostic_limit` 个未修改 diff、未提供新有效检查结果的诊断动作（默认 3）；随后以 `repair_stalled` 明确记录未完成，保留补丁并交独立判分。提交仅在当前 diff 的目标与选定回归均实际执行通过、没有未解决失败时接受；否则记为 `incomplete_validation`，不强制提交或清除失败。官方 resolved 与正常 submit 继续分别统计。

`progress.target_action_strategy` 默认关闭，需同时开启回归策略。开启后，先引导根据公开题面编写有明确断言的目标测试，在仅有测试改动的基线上逐目标运行，要求实际断言失败；收集、导入、空测试或基线通过不能证明复现。记录目标文件指纹、基线失败与 diff，后续实现改动必须保留目标文件，优先重跑目标再运行回归。缺失基线失败证据或更改目标均不能获得提交资格。断言的语义充分性仍由任务证据和独立官方判分评估，不能由静态检查保证。

该开关同时将历史合法动作显示为独立的协议对象，与执行器的 `Action.payload()` 一致；工具观察另列，不再把动作嵌入观察记录。末尾输出说明使用相同协议实例，格式错误后优先纠正未执行的动作。严格解析、两次格式失败停止和原有重复动作拦截不变；不删除模型输出中的尾随括号，不从多动作响应中选取动作执行。自动目标测试同样计入原有步数与墙钟，未完成目标验证不能因回归局部通过而升级为完成。

`progress.delivery_behavior_strategy` 默认关闭，需同时启用目标策略。它提供经公开题面审阅的任务专属命令行行为测试脚手架：正常输出、导入副例及带预期诊断的逐文件检查；不约束内部模块标签。Agent 须通过合法动作把脚手架加入测试目录，首次 diff 仍是 Agent 的实际操作。基线上允许功能对照通过，但全部目标必须执行，且至少一个有效断言失败。源码修复后完整目标及相关回归仍须通过；固定目标的指纹不可改变。这类脚手架只支持已注册任务，不代表 Agent 能自行生成充分测试。

该开关还精简重复的派生验证状态，保留全部动作和观察；提示每次生成一个短动作，较大修改分步执行。字符数仅是生成建议，不放宽或另行修补严格协议。共用传输层保存有界响应正文及推理文本的本地审计记录（各最多 65536 字符、每次运行合计 8 MiB），记录完整字符数、空白数及哈希；审计数据不授权执行动作，不替代完整结束标记和费用回执。输出耗尽或中断仍不得执行局部 JSON。时限使用包含系统休眠的已过时间，并保持单调不减；恢复运行后立即检查剩余时限，不因睡眠延长任务。

## 可选的失败驱动源码编辑决策

`progress.source_edit_strategy` 默认关闭，依赖目标验证策略。开启后另外记录生产 Python 源码的首次修改和后续修改步骤；测试目录、测试辅助代码和测试文件不满足源码修复条件。原有 `first_edit_step` 仍表示任意实际 diff 的首次出现，不能据此宣称完成生产修复。

目标失败后，末尾指引要求依据已观察错误与源码提出可证伪的根因假设、拟修改的 `path::function`、失败步骤及原检查的复测命令。模型可在现有 bash 字符串中用短注释记录这些信息，不增加动作 Schema 字段，也不把假设当作已证实的因果关系。缺少定位依据时允许回答具体问题的有限诊断，不自动生成或强制执行源码补丁。

此模式按生产源码 diff 计数：已知失败期间每个没有改变生产源码的模型动作均消耗诊断额度，包括改测试、重复失败测试或再次读取。只有生产源码改动重置额度。达到原有诊断额度后，模型还可根据最新返回结果作一次最终修正决策；若该动作仍未改变源码且失败未解决，下个循环以 `repair_stalled` 终止。所有动作继续占用原有步数、墙钟和费用，重复动作拦截不变。

源码修改继续触发原有目标及回归验证，历史失败按覆盖关系清除。提交还要求生产源码补丁非空；正常提交、局部验证闭环与独立官方判分分别统计。此机制只支持当前 Python 任务的源码分类，并不保证假设正确或测试覆盖完整。

## 可选的执行效率策略

`progress.efficiency_strategy` 默认关闭，依赖已启用的源码编辑策略。它只改变信息组织和工具使用引导，不减少必需测试，不缓存执行结果，不放宽动作校验、失败清除、诊断额度或资源限制。

开启后，动作指引只在上下文末尾出现一次，完整动作和原有观察仍然保留。记录字面量 `sed` 读取窗口、是否被现有输出截断限制裁切及对应 diff；编辑后旧窗口标为历史状态。复合读写命令不会被标记为当前源码读取。索引是导航提示，不是源码正确性或测试通过证据。

自动测试保留原选择器与独立执行方式，增加详细诊断及局部变量，帮助区分具体错误；完整输出仍按原限制保存。失败重点只摘录实际观察到的错误行，不推断根因。提示模型先利用已有证据选择可检验的小修正、只编辑而不附带重复手测，目标和回归仍由编排器依次验证。完成验证后的提交指引保持简短，不诱导重新诊断。实际速度与调用数效果必须经受控实验衡量。

## 可选的失败证据与单步动作决策

`evidence_action_strategy` 默认关闭，依赖现有源码编辑策略。开启时以一个简短的公开证据包替换重复的修正指引：已记录失败的步骤、退出码、diff、原测试命令、固定公开断言、已观察源码窗口和近期诊断问题。源码窗口标记截断及过期状态，模型自述不作为根因证据。普通命令打印错误不自动获得测试通过或清除失败的资格。

该策略不增加诊断机会。最终机会明确要求基于已有证据作出下一步决策；缺少事实仍可提出具体问题进行一次定向诊断，随后没有生产改动则如实停止。输出提示要求交付可验证的小动作，避免在一次响应内推演整个修复；合法性仍由原严格动作协议判定。测试使用详细错误与局部变量输出，但断言、选择器、失败覆盖、提交门及资源限制不变。

## 可选的有限动作恢复

`progress.failure_recovery_strategy` 默认关闭，依赖源码编辑策略。格式失败后保留被拒响应的有界反馈；若它是一个通过原 Schema 校验的对象后仅多出单个 `]`，向下一请求展示其尚未执行的候选动作。候选只用于重新生成，不删除尾随字符后执行。模型必须重新交付严格合法且工具和参数不变的完整动作；两次格式失败停止及原步数、时间、费用限制不变。多对象、数组、其他后缀、过长候选与非法 Schema 不抽取为候选。

对于直接 Python 脚本以非零退出码结束、完整 traceback 最后一行为明确参数绑定 TypeError、且 diff 未变化的模型诊断，记录调用错误并提前阻止相同命令重放。普通源码搜索中的错误文本、退出零、超时、截断和自动测试不触发这一规则。记录可跨只读动作保留；diff 改变或执行另一条非只读命令时失效，因为后者可能改变未跟踪文件或环境。它不推断任意程序的语义等价或完整环境状态。

被阻止的提案记录 `executed=false`，消耗原有诊断额度，连续拦截沿用 `max_blocked_repeats` 停止。错误反馈优先要求修正调用或定向查看签名，不生成源码补丁，不改变测试证据或清除已有失败。编辑后的目标和回归仍由编排器独立执行；该策略不拆分或改写模型提供的复合 shell 命令。实际模型是否更可靠仍须以新冻结实验验证。

|---|---|
| `first_edit_checkpoint`、`post_edit_checkpoint`、`regression_strategy` | 可分别配置，作用范围见对应章节 |
