# 运行进展与命令分类

[`orchestrator/progress.py`](../src/ctxroute/orchestrator/progress.py) 为 A1–A5 提供运行状态和重复动作控制。参数配置于各实验臂的 `progress` 字段；A0 保留上游原生循环行为。

## 重复动作控制

| 参数 | 默认值 | 行为 |
|---|---:|---|
| `repeat_warn_after` | 2 | 连续相同命令、完整输出、退出码与补丁达到阈值时提示重复 |
| `repeat_block_after` | 3 | 达到阈值后拦截再次执行同一命令 |
| `max_blocked_repeats` | 2 | 连续拦截达到阈值时以 `stagnation` 结束 |
| `final_step_warning` | 10 | 剩余动作达到阈值时提示优先编辑、验证和提交 |

默认设置允许最多三次相同命令与结果组合。随后相同命令不再执行，模型收到纠错反馈；连续两次仍请求该命令则停止。模型请求已经发生，因此被拦截动作仍计入费用和步数。更换动作可以继续，新的输出或补丁会重置观察连续计数。

检测仅比较命令、输出、退出码和补丁的连续签名，不推断任务是否成功，也不能识别所有循环。它可能限制有意轮询，应作为可记录的实验控制条件。

## 运行状态

P0 `RUN STATUS` 包括剩余动作、墙钟、保守本地费用额度、补丁是否非空、增删行数及重复次数。编排器在动作请求前刷新状态，将压缩消耗的时间和费用计入。该部分的 token 纳入上下文预算，不属于 P1 引用事实，也不是模型推断。

每次正常返回的 `bash` 命令之后，编排器获取实际 `git diff`；命令失败也可能已经修改文件。超时或输出超限按沙箱终止规则处理。补丁存在不代表修复正确，忽略文件和仓库外状态也不由该 diff 覆盖。

## 保守命令分类

[`router/rules.py`](../src/ctxroute/router/rules.py) 的分类器版本为 `literal_cd_single_command_v2`。它识别有限只读命令、测试命令，以及一个字面量 `cd` 前缀加 `&&` 后的单条命令，例如：

```sh
cd /testbed && cat src.py
```

分类过程不改写发往沙箱的原始命令。Python 脚本、多段复合命令、重定向、替换、管道及无法识别的命令归为 `edit_or_unknown`；带编辑选项的 `sed` 不按只读处理。分类用于路由启发式，不替代沙箱隔离。

路由还要求满足无错误历史、上下文阈值和强模型锁条件，识别为只读并不保证下一步切换到廉价模型。重复动作被拦截时触发强模型锁。

## Trace 与分析

trace 保存 `command_class`、`command_classifier_version`、`progress` 和 `executed`。拦截记录为 `executed=false`、`repeated_action_blocked`，分析以 `blocked_repeat_actions` 与实际执行的重复命令区分。

分析优先使用执行时记录的分类；缺少分类字段的旧轨迹采用分析版本的回退逻辑。复现历史分析应使用对应源码版本。改变提示、停止规则或分类器后应冻结新计划，以保留比较条件。
