# 进展反馈与只读路由改进

日期：2026-10-25，代码阶段。依据上一轮固定 dev 轨迹中的长时间重复命令和持续 strong_lock，实现运行进展反馈与保守的命令分类修正。本阶段没有调用模型、启动 VM 或运行 benchmark。

## 统一适用于 A1–A5 的进展控制

configs/arms/A1–A5.yaml 与 A2/A4 truncate 配置显式记录 progress 参数；A0 原生文本循环保持原行为。

| 参数 | 默认值 | 行为 |
|---|---:|---|
| repeat_warn_after | 2 | 同一命令、完整输出、退出码及当前补丁连续相同时，在下一请求提示重复 |
| repeat_block_after | 3 | 连续观察到 3 次相同结果后，拦截再次请求执行同一命令 |
| max_blocked_repeats | 2 | 连续请求被拦截两次后以 stagnation 结束 |
| final_step_warning | 10 | 剩余动作数不超过 10 时提示优先编辑、验证并提交 |

默认最多执行三次相同命令/输出/补丁组合；第 4 次请求只返回纠错反馈，第 5 次仍重复则停止。拦截针对工具执行，已经产生的模型请求照常计费，步数照常计数。换一个有效动作可以继续，已改变的输出或补丁会重置重复连续计数。不会把空补丁补成成功，也不会自动提交。

P0 RUN STATUS 显示剩余动作（含当前）、剩余墙钟、本地保守成本额度、当前补丁是否非空及增删行数、重复次数和操作提示。该部分是编排器观测，不进入 P1 的引用事实集合，也不被压缩成模型推断；其 token 开销纳入上下文预算。压缩消耗的时间和费用会在动作请求前刷新。提示强调阅读相关源文件、实际编辑、针对性检查与提交。

每次 bash 执行后重新获取真实 git diff，即使命令失败也检查可能已发生的编辑；超时或输出超限按原终止规则处理。相比旧版只对成功的“编辑/未知”命令取 diff，现在增加了只读/失败命令后的沙箱控制调用，实际性能开销未测。补丁存在不代表正确，也不包含 git 忽略文件或外部状态；重复检测是有限启发式，不能识别所有循环，也可能限制有意的轮询。

## 只读分类与证据

分类器版本 literal_cd_single_command_v2 识别一个字面量 cd 目录前缀加 && 后的单条命令，例如 cd /testbed && cat src.py。只解析分类，发送给沙箱的原始命令不改写。已有只读白名单和测试命令识别继续适用；Python -c、脚本、多段 &&、重定向、替换、管道等仍归类 edit_or_unknown。sed 额外编辑选项也不会作为只读。分类只是路由启发式，不代替容器隔离。

上一轮命令离线重新分类：A1/A2/A3/A4 分别有 3/8/5/9 条从未知变为只读；其余大量 Python/复合命令保持未知。该结果不代表会产生相同数量的廉价模型调用，因为还需满足 clean_steps、强模型锁和上下文门槛，且新模型轨迹未运行。原轨迹和统计不改写。证据：[classifier-replay.json](../results/validation/progress-routing-20261025/classifier-replay.json)。

新 trace 记录 command_class、command_classifier_version、progress 与 executed。被拦截请求为 executed=false、repeated_action_blocked；分析将其与实际执行的重复命令区分，并单列 blocked_repeat_actions。新轨迹分析优先使用当时记录的分类。旧轨迹无分类字段时使用分析版本的回退逻辑，复现历史报告应使用对应源码提交。
